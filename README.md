# OrangeHRM Employee Lifecycle Automation

Java 17 + Selenium 4 + TestNG + POM + REST Assured + ExtentReports.

## Scenario coverage
1. Login and verify Dashboard.
2. Add an employee using JSON test data, with a unique Employee ID and profile picture.
3. Search by Employee ID and update Job Title / Employment Status.
4. Validate the employee through the OrangeHRM API when an authorized bearer token is configured.
5. Delete the employee in the UI and verify it is absent from UI search results.
6. Verify logout returns to the login page and refresh does not restore the session.
7. Generate an Extent HTML report.

## Prerequisites
- JDK 17+
- Maven 3.9+
- Google Chrome
- A valid PNG/JPG image at `src/test/resources/profile.png` (keep it under the demo's upload size limit).
- Network access to `https://opensource-demo.orangehrmlive.com`.

Selenium Manager bundled with Selenium 4 normally resolves ChromeDriver automatically.

## Setup
1. Add a small, valid test profile picture at `src/test/resources/profile.png`.
2. Check `src/test/resources/config.properties`.
3. Run `mvn clean test`.

## API validation
The OrangeHRM employee API is documented at:
https://api-starter-orangehrm.readme.io/reference/get-an-employee

The API uses bearer authentication on supported deployments. The public demo may not issue an API token to ordinary demo users, and API permissions may be restricted. Set `api.bearer.token` in `config.properties` (or environment variable `API_BEARER_TOKEN`) only if you have an authorized token. API tests deliberately skip with a clear reason if no token is configured; they do not pretend that a UI check is an API check.

The API collection filters and response schema can differ between OrangeHRM versions. Confirm the supported filter names and response shape against the API docs for the instance being tested. For an organization-owned OrangeHRM instance, use a test tenant and a dedicated API account.

## Reports
- Extent HTML: `test-output/extent-report.html`
- TestNG reports: `test-output/index.html` and `test-output/emailable-report.html` (generated by TestNG/Maven Surefire).

## Video recording
Selenium WebDriver does not natively record video in local Chrome. For a reliable video artifact, run the test against Selenium Grid with video recording enabled (for example, a Selenium Grid Docker setup with a video sidecar), or use an approved desktop recorder such as OBS/FFmpeg. Store the resulting video in `test-output/video/`. Do not claim a video was recorded unless the recording process actually ran.

## Notes / troubleshooting
- This is a shared public demo. Avoid using real personal data and do not run destructive tests against a production HR system.
- The public demo's available Job Title and Employment Status options can change. If `QA Engineer` or `Full-Time` is not present, update `employee.json` to an option visible in the dropdown.
- The employee record's API `empNumber` is different from the UI Employee ID. If your API supports lookup by `employeeId`, use that filter to find the record and then query its `empNumber` endpoint. Adapt `OrangeHrmApi` to the response schema documented for your tenant.
- The test intentionally uses explicit waits, not fixed sleeps.
